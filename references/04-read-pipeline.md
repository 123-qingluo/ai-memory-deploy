# 04 读取管线

> 实现在 `memory_core/read.py`。核心判断：读取积极，但剂量受控。

## 1. 三路读取

| 路径 | 触发 | 定位 | 剂量 |
| --- | --- | --- | --- |
| 自动预取 | 每轮私聊构建 prompt | 保证"该想起来时想得起来" | top5 候选 → 阈值 → 3 条 × 160 字 |
| 工具查询 | 模型主动调用 `search` | 精确性：需要确切答案时自己查 | 模型自定 topN |
| 随机闪回 | 每轮 5% 概率 | 模拟"不请自来的回忆" | 1 条（**v1 未实现**） |

缺任何一路都会退化：只有工具 → 模型懒得查；只有预取 → 永远只想起最近/最热；只有闪回 → 不可控。

v1 明确不实现闪回，避免把未验证的行为塞进基线；配置与文档保留，后续按 `flashback` 扩展点接。

## 2. 剂量

| 参数 | 默认 | 理由 |
| --- | --- | --- |
| 预取条数 | 3 | 超过 3 条，prompt 变成检索报告 |
| 每条摘要 | 160 字 | 够判断相关性，不够就让它 `search` |
| 阈值（http 嵌入） | 0.60 | 低于 0.6 多是"话题沾边但无关" |
| 阈值（hashing 嵌入） | 0.28 | 词面嵌入分布不同，不能套 0.6 |
| 同消息去重窗口 | 120 秒 | 用户连发多条时不重复注入 |

`hashing` 嵌入只用于离线自检/应急：它是字符 n-gram 相似度，不是语义模型。**生产必须切 http 嵌入**，并把阈值按评测集重调。

## 3. 检索算法（本实现）

```
1. 候选池：当前 folder 内 active 记录（可选 knowledge / archived）
2. 向量召回：query 与每条记录余弦
3. 词面召回：FTS5（trigram）命中 + 字符二元组覆盖度
4. 混合打分：score = α·cos + (1-α)·lex
   α = 0.85（http 嵌入）/ 0.50（hashing）
   FTS 精确命中给 0.50 + 0.50·lex 的下限
5. 标签加权：core +0.12 / diffusion +0.04 / opposing -0.25
6. 过滤 score ≤ 0
7. 结果去重：两两余弦 ≥0.88（无向量时标题 Jaccard ≥0.85）
8. 排序取 top_k
```

为什么不是朴素 top-k：中文短查询 + 长正文，纯余弦会被高频词支配；标签提供硬方向修正；去重保证注入的 3 条不是同一件事。

**可替换方案**：小规模（<1 万条）可用纯 FTS/BM25；延迟敏感可去掉向量；但**不要去掉去重**。

## 4. 自动预取的 query

- 默认取最后一条用户消息。
- 超过 120 字且含多句时，取前 3 个话题的首句拼接（上限 200 字），修掉"多话题批次只预取最后一个话题"的问题。
- 群聊默认不预取（`prefetch.allow_group=false`），群聊与私聊用不同 `folder_id` 隔离。

## 5. 注入块格式

```
[记忆预取] 以下可能是相关记忆（不是全部；未列出不代表没有）：
- (事实/偏好) 主人乳糖不耐：主人乳糖不耐，喝牛奶会肚子疼，奶茶要换成燕麦奶。
- (事件) 周末展览约定：主人答应帮查周末的展览信息，还没有给答复。
需要确认时先检索；没有记录就说不记得，不要编造。
```

三件事必须保留：

1. **"不是全部"**：否则模型把未列出当成未发生。
2. **摘要而非全文**：全文会挤占人设与对话。
3. **"不要编造"**：没有记录时的唯一正确行为是说不记得。

## 6. 注入位置

同一轮 prompt 里可能有多个插件改写，顺序由 hook 权重决定（数值越大越先）：

```
人设/技能路由(40) → 文档(35) → 关系判定(30) → 输出长度(20)
 → 审批(14) → 自述台账(13) → 工具告警(12) → 自动预取(11) → 闪回(10)
```

后写的内容离用户消息更近、注意力更强。记忆放靠后，让它像"刚想起来"，而不是开场白。

## 7. 计数器与生命周期

| 事件 | activation_count | search_hits |
| --- | --- | --- |
| 工具 `search` 返回该条 | +1 | +1 |
| 自动预取注入该条 | +1 | +1 |
| 闪回注入（v1 未实现） | +1 | 不加（另加 flashback_hits） |

生命周期淘汰只看 `activation_count`；`search_hits` 用于观测与后续闪回加权。

## 8. 读取反模式

| 反模式 | 后果 |
| --- | --- |
| 用整段对话当 query | 检索发散，命中率下降 |
| 每次注入 10 条 | 模型开始复述记忆，对话变念档案 |
| 预取也抽 knowledge 桶 | 答非所问 |
| 归档记忆默认参与 | 旧信息压过新信息 |
| 检索失败静默返回空 | 用户以为"她忘了"，实际是服务挂了 |

本实现：嵌入失败写 `read:embedding_error` trace，降级到词面检索；检索为空写 `search:empty` / `auto_recall:below_threshold`。
