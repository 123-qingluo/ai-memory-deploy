# 01 产品判断与决策

> 这一篇回答"为什么要这样部署"。代码只是把这些判断固化；判断错了，调参救不回来。
>
> 来源：按《AI 角色记忆系统设计参考》v1.0 的契约与行为重写（clean-room），不包含参考实现的源代码；参考实现运行在 AGPL-3.0 框架内。本 skill 代码采用 MIT 许可（见仓库根 LICENSE）。

## 1. 记忆要解决的四类问题

| 问题 | 表现 | 失败后果 |
| --- | --- | --- |
| 跨会话一致性 | 昨天说过怕冷，今天不该再问"你怕冷吗" | 角色像失忆的客服 |
| 关系连续性 | 上周答应的"周末帮你查"，这周要能接上 | 关系推进归零 |
| 事实正确性 | 不能把玩笑记成偏好，不能编造没发生过的事 | 人设漂移、信任崩塌 |
| 可控遗忘 | 隐私能删、过期信息退场、错记能纠正 | 合规风险、噪声淹没信号 |

## 2. 明确的非目标

- **不是聊天归档**：归档是 append-only，记忆是编辑过的档案。
- **不是知识库**：知识库回答"文档里写了什么"，记忆回答"我和这个人之间发生过什么"。v1 不做文档导入。
- **不是长上下文替代品**：把 100 轮塞进上下文会线性涨成本，且模型仍会记错；记忆是把上下文压缩成可核对的事实。
- **不做人格模拟**：记忆只提供事实与关系状态，不决定"她此刻什么态度"。

## 3. 五条设计原则

### P1 档案，而非流水

同一事实反复出现十次，档案里只应有一条，且有最新版本。
落地：`person` 一人一条；同事实合并；写入前去重（默认 0.90）。

### P2 写入保守，读取积极

**一条错记比没有记忆更糟**。缺少记忆只会让角色问一句"你之前说过吗"；错记会让角色理直气壮地编造，并污染后续推理。
落地：六道写入闸门；三路读取（v1 实现两路）；注入剂量 3 条 × 160 字。

### P3 记忆必须可核对

每条记忆都要能追溯到一句用户原话（`evidence`），且必须是那次输入的子串。
落地：抽取器强制校验；工具写入若提供 `source_text` 也强制校验；不匹配整条丢弃。

### P4 遗忘是分级衰减，不是一刀切 TTL

活跃 → 归档 → 删除；降级依据是"是否被使用过"，不是单纯时间。
落地：90 天未更新且从未被激活 → 删除候选；激活过 → 归档；`pin` 免疫。
上线时 `dry_run=true`、`allow_hard_delete=false`。

### P5 记忆策略要写进系统提示

把"记什么/不记什么/先查再答/没有就说不知道"写成常驻提示，并配合工具使用监督。
落地：`templates/command_manual.md` 常驻；每轮附最新 10 条标题并声明"这不是全部"；连续 20 轮未用工具告警。

## 4. 决策记录（摘要）

| 编号 | 决定 | 理由 | 后果 |
| --- | --- | --- | --- |
| D1 | 用结构化档案，不用全量摘要/原始对话向量库 | 档案才能回答"关于他的确定事实"，可合并可纠正 | 需要抽取器与类型系统 |
| D2 | 强制 evidence | 错记不可查是最贵的故障 | 召回率下降，宁缺毋滥 |
| D3 | memory / knowledge 分桶 | 知识被随机闪回会答非所问 | 多一个检索开关 |
| D4 | 强制三元标签 | 中文短查询方向性弱，纯向量表达不了"要避开什么" | 写入摩擦；空组需显式写 `-` |
| D5 | 闪回用反活化加权 | 正比加权会让热记忆垄断 | v1 未实现闪回，先留开关 |
| D6 | 遗忘分级而非 TTL | TTL 会误杀"重要但少提"的事实 | 需要计数器与后台作业 |
| D7 | cross-encoder 重排可选 | 注入只有 3 条，top1 错则全错 | v1 默认关闭，接口保留 |
| D8 | 默认 shadow → 审批 → 逐步放开 | 自动抽取的错记会污染人格 | 初期要人看候选 |

## 5. 部署前必须确认的五问

复制这张表，让用户逐项回答；用户答"按默认"才使用默认值。回答写进 `DEPLOY-REPORT.md`。

| # | 问题 | 默认答案 |
| --- | --- | --- |
| 1 | 记什么？ | 稳定偏好、习惯、边界、过敏、重要日期、约定、反复话题、重要事件；用户明确要求记住的 |
| 2 | 不记什么？ | 密码/验证码/银行卡/证件/住址/token；临时情绪、玩笑、扮演、一次性闲聊；第三方隐私 |
| 3 | 用哪些类型？ | person / event / knowledge / procedure；place、asset 只留字段不启用 |
| 4 | 可核对强度？ | 抽取强制 evidence 原话子串；工具写入尽量带 source_text；不匹配整条丢弃 |
| 5 | 删除策略？ | 90 天窗口；先 dry-run 看报告；归档可检索；硬删默认关闭；`pin` 免疫 |

## 6. 什么时候不该用这套东西

- 只是要"把聊天记录存下来"：用归档/搜索，别用记忆。
- 要的是文档问答：用 RAG 知识库，v1 没有切块导入。
- 已有成熟记忆系统、只是效果不好：先按 `08-troubleshooting.md` 排查，再考虑重部署。
